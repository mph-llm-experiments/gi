# Tip Jar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A quiet tip jar on the Settings/About screen: three one-time tips through StoreKit 2. Tips unlock nothing, and the app never prompts for one.

**Architecture:**
- `TipJar` (an `@Observable` `@MainActor` class in the app target) loads three consumable products, buys them, finishes transactions, and listens to `Transaction.updates` from launch.
- `TipJarSection` renders inside `SettingsView`.
- Local testing uses a StoreKit configuration file (`ios/GIBowl/Tips.storekit`) wired into the scheme, plus `StoreKitTest.SKTestSession` in hosted unit tests.

**Tech Stack:** StoreKit 2, StoreKitTest, SwiftUI, Swift Testing, XCUITest.

**Spec:** `docs/superpowers/specs/2026-10-31-carb-bowl-design.md` ("Tip jar"). Builds on plans 2 and 3.

## Global Constraints

- Product ids:
  - `net.puddingtime.GIBowl.tip.small` ($1.99, "Small tip")
  - `net.puddingtime.GIBowl.tip.medium` ($4.99, "Medium tip")
  - `net.puddingtime.GIBowl.tip.large` ($9.99, "Large tip")
  - All consumable.
- Tips appear only in Settings, in a "Tip jar" section. No badges, prompts, counters, or "you've used this N times". A tip unlocks nothing.
- Copy, exactly:
  - Section footer: "GI Bowl is free and has no ads. If it helps you, a tip helps keep it that way."
  - After a successful purchase: "Thank you. That really helps."
  - When products can't load: "Tips aren't available right now."
- Prices always come from `Product.displayPrice`. Never hard-code them in the UI.
- Creating the products in App Store Connect is Mike's step before launch. It's outside this repo.

## Review Focus

1. **Products fail to load** (offline, no App Store Connect products yet): the section shows "Tips aren't available right now." with no spinner stuck forever and no crash. Test in Task 1 (`SKTestSession` with failing loads).
2. **User cancels, or the purchase is pending** (Ask to Buy): no thank-you, no error alert, and the buttons are usable again. Test in Task 1.
3. **A transaction arriving at launch** (interrupted earlier): `Transaction.updates` finishes it, so it doesn't re-deliver forever. Test in Task 1.
4. **Double tap during a purchase:** a second purchase isn't started while one is in flight. Test in Task 1.
5. **Prices in other storefronts:** the displayed text is `displayPrice` and is never formatted by us. Test in Task 2 (UI shows "$1.99" from the config file).

### Task 1/2: StoreKit config and the TipJar model

**Files:**
- Create: `ios/GIBowl/Tips.storekit`, `ios/GIBowl/Tips/TipJar.swift`, `ios/GIBowlTests/TipJarTests.swift`
- Modify: `ios/project.yml` (scheme `run` and `test` → `storeKitConfiguration: GIBowl/Tips.storekit`), `ios/GIBowl/GIBowlApp.swift` (create one `TipJar`, start listening at launch, inject via `.environment`)

**Interfaces:**
- Produces:
  - `@MainActor @Observable final class TipJar`:
    - `enum State { case loading, ready([Product]), unavailable }`
    - `private(set) var state: State`
    - `private(set) var purchasing: Product.ID?`
    - `private(set) var thanked: Bool`
    - `static let productIDs: [String]` (the order in Global Constraints)
    - `func load() async`
    - `func tip(_ product: Product) async`
    - `func listenForTransactions() -> Task<Void, Never>`
  - Ready products are sorted by price.
  - `tip` sets `purchasing`, calls `product.purchase()`, and handles the result:
    - `.success(.verified(t))` → `await t.finish()`, `thanked = true`
    - `.success(.unverified)` → finish, no thanks
    - `.userCancelled` and `.pending` → nothing
    - It clears `purchasing` in every case and returns immediately if `purchasing != nil`.

### Task 2/2: Tip jar section in Settings

**Files:** Create `ios/GIBowl/Tips/TipJarSection.swift`; modify `ios/GIBowl/Views/SettingsView.swift`, `ios/GIBowlUITests/KitchenFlowTests.swift`.

**Interfaces:**
- Consumes: `TipJar` from the environment

Behavior:
- `Section("Tip jar")` sits after About.
  - Loading: `ProgressView`.
  - Ready: one row per product, with `displayName` on the leading side and a bordered button showing `displayPrice` on the trailing side (`accessibilityIdentifier("tip.<id suffix>")`). The button is disabled while any purchase is in flight.
  - Unavailable: the unavailable copy.
- After thanks, a row "Thank you. That really helps." (`tip.thanks`).
- Footer copy as in Global Constraints.
- `.task { await jar.load() }` runs when the section appears, only if the state is `.loading`.
