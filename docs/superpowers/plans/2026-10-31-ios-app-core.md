# iOS App Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native iPhone app ("GI Bowl", working name) where you build one meal or snack from rough portions and see Room to spare / Close to your number / Over your number. It includes search, GI lookup, your own foods, and targets.

**Architecture:** `ios/` holds a local Swift package `GIBowlCore` with all logic: food data decoding, bowl math, search, and SwiftData models with store operations. It's tested with Swift Testing via `swift test`. The SwiftUI app target `GIBowl` is generated by XcodeGen from `ios/project.yml`. It bundles `public/foods.json` from plan 1 as a resource, and its views stay thin over the core.

**Tech Stack:** Swift 6.4 (strict concurrency), SwiftUI, SwiftData, Swift Testing, XCUITest, XcodeGen, Xcode 27, iOS 27 simulator.

**Spec:** `docs/superpowers/specs/2026-10-31-carb-bowl-design.md`. Plan 1 (`docs/superpowers/plans/2026-10-31-food-data-pipeline.md`) produced the `foods.json` v2 this plan reads. Plans 3 (photo capture) and 4 (tip jar) build on this one.

## Global Constraints

- iOS 27.0 deployment target, iPhone only (`TARGETED_DEVICE_FAMILY = 1`). Swift 6 language mode.
- No third-party dependencies. No network access, analytics, notifications, review prompts, onboarding carousel, or streaks.
- Carbs display as "about Ng": nearest 5g, minimum "about 5g", under 3g → "a few grams". No decimals and no gram inputs for portions anywhere in the UI.
- State thresholds, with target `t` and unrounded total `c`:
  - `c < 0.75t` → **Room to spare**
  - `0.75t ≤ c ≤ t` → **Close to your number**
  - `c > t` → **Over your number**
- Hints, exactly:
  - "Room for about Ng more"
  - "Right about at it" (shown when under 3g remains and not over)
  - "Roughly Ng past it"
- Colors: sage / amber / terracotta for the three states. Light values `#7a9a5a` / `#c4a23a` / `#c26a4a`, dark values `#9cbd7c` / `#d6b55a` / `#e08f70`. Backgrounds are warm neutrals; display text uses the system serif (`.fontDesign(.serif)`).
- Never recommend targets or foods. There are no default targets.
- Bundle id `net.puddingtime.GIBowl`. Simulator builds are unsigned.

## Review Focus

1. **Target set to 0, blank, or absurd (e.g. 999):** a 0 or empty target counts as unset (no state shown, no division by zero). Large targets work normally. Test in Task 2 (`stateFor` with `target: 0`) and Task 4 (`Targets` clamps 0 to nil).
2. **Long garbled study names** (e.g. "Pacific Health Laboratories, Parsippany, NJ, USA) Sustagen®…") at the largest Dynamic Type size: names wrap, and portion buttons stay tappable and are never truncated into uselessness. Checked in Task 6 with an accessibility-XXL simulator screenshot.
3. **A custom food deleted while it's in the bowl:** the bowl item still shows its name and carbs. Test in Task 4 (`BowlItem` keeps a name snapshot).
4. **Search inputs:** empty, whitespace-only, diacritics ("crème"), punctuation ("½"), and one-character queries return an empty list or sensible matches, never a crash or a stall. Test in Task 3.
5. **Your own food with no GI and one portion:** the detail shows GI "—" and one portion button. A study food with no portions shows "Add carbs for this". Covered by the UI test in Task 8 and the view model test in Task 6.

### Task 3: Search

**Files:** Create `ios/Sources/GIBowlCore/SearchableFood.swift`, `ios/Sources/GIBowlCore/FoodSearch.swift`, `ios/Tests/GIBowlCoreTests/FoodSearchTests.swift`

**Interfaces:**
- Consumes: `Food`, `Portion` (Task 1)
- Produces:
  - `public struct SearchableFood: Identifiable, Hashable, Sendable { id: String, source: Source (.dataset | .custom), tier: Int, name: String, gi: Int?, gl: Int?, portions: [Portion] }`
    - `init(food: Food)` sets tier 0 for canonical and 1 for study.
    - `init(customID: String, name: String, gi: Int?, portions: [Portion])` sets tier 0.
  - `public func normalize(_ s: String) -> [String]` — lowercases, folds diacritics, splits on any non-alphanumeric character, drops empty tokens.
  - `public struct FoodSearch: Sendable { public init(_ foods: [SearchableFood]); public func search(_ query: String, limit: Int = 50) -> [SearchableFood] }`

Matching: every query token must match some name token, scoring 3 for a prefix, 2 for contains, and 1 for an edit distance ≤ 1 when the query token is ≥ 4 characters. A food's score is the sum. Order by tier ascending, then score descending, then name length ascending. Return `[]` for a query with no tokens or whose only token is 1 character. Normalize names once in `init`.
